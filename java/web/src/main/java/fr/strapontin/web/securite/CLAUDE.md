# Authentification (`fr.strapontin.web.securite`)

Invite-only. Login par identifiant (insensible à la casse). Rôles : `user` | `admin`.
2FA TOTP optionnel pour tous les utilisateurs — enrollment via `/parametres/totp`, challenge automatique à la connexion si activé. Cap : 500 artistes / 200 salles par user.
Algorithme TOTP conforme RFC 6238 (HMAC-SHA1, 30 s, ±1 fenêtre, saisie tolérante aux espaces). `UtilisateurDetails.isCredentialsNonExpired` retourne toujours `true` — le forçage du changement de mot de passe pour un compte invité (`doitChangerCredentials`) n'est pas géré par ce mécanisme Spring Security mais explicitement côté frontend/contrôleurs. `TotpGuardFilter` bloque tout appel `/api/**` (sauf `/api/auth/totp` et `/api/auth/logout`) en 401 JSON tant que la session porte `TOTP_EN_ATTENTE=true` (challenge 2FA non validé) — routes non-API laissées passer, le SPA Vue gère la redirection côté client. `TotpChallengeService` verrouille le compte après 5 échecs consécutifs (`totp_failure_count`, remis à 0 sur succès) — réinitialisation 2FA par un admin depuis `/admin` (bouton « Réinit. 2FA », endpoint `POST /api/admin/utilisateurs/{id}/reset-totp`) pour un compte bloqué. Succès et échecs d'auth (login, rate-limit, TOTP) consignés dans `logs_admin` (source `auth`). Rate-limit login (`RateLimitingLoginFilter`) : `/api/auth/login`+`/api/auth/forgot-password` 15 tentatives/15 min par IP, `/api/auth/reset-password` 30/heure (429) en fenêtre glissante via `LimiteurDebit` (journal d'horodatages par clé, partagé avec les signalements et les erreurs client) — journaux en mémoire Caffeine, perdus au redémarrage, risque résiduel jugé acceptable pour un système invite-only (migration PostgreSQL à envisager si l'exposition publique évolue).
Spring Security form login → cookie `SESSION` (JDBC-backed, survit aux restarts, `Max-Age=2592000`, `HttpOnly`, `SameSite=Lax` — pas `Strict`, compatibilité Safari sur navigation entrante — configuré via `DefaultCookieSerializer`, pas via `application.properties`). Mots de passe hashés en bcrypt. `spring.session.timeout=30d` n'est pas appliqué par Spring Session 4 — `SessionSecurityConfiguration.sessionTimeoutCustomizer` le remplace programmatiquement (`setDefaultMaxInactiveInterval`, session prolongée à chaque requête). `SessionSecurityConfiguration.authenticationManager` (`ProviderManager` construit à la main, hors auto-configuration Spring Boot standard) doit lui attacher explicitement un `AuthenticationEventPublisher` — sans lui, `AuthenticationSuccessEvent`/`AbstractAuthenticationFailureEvent` ne sont jamais publiés et `AuthEvenementListener` (consignation `logs_admin`) reste du code mort.
`session_appareils` associe un `appareil_id` opaque à chaque `SPRING_SESSION.SESSION_ID` (jamais le `session_id` réel côté client — un XSS qui lirait la liste ne peut pas usurper une session). `AppareilEnregistrementInterceptor` (pas le contrôleur de login) enregistre l'appareil au premier appel API _suivant_ la connexion, car Spring Session (JDBC) ne persiste la session qu'après que le login a déjà rendu sa réponse. `/parametres` (Compte) et `/admin` exposent la gestion des appareils/sessions.
`PasswordResetController.reinitialiserMotDePasse` : si le token est de type `invite:` et qu'un `identifiant` est fourni, active le compte invité (identifiant + mot de passe) et ouvre directement une session en une seule requête, plutôt que de forcer un second aller-retour login après activation. Changement d'identifiant (`VerificationRepository.majUsernameEtActiverParEmail`, `UtilisateurRepository.majIdentifiant`) : `display_username` n'est resynchronisé sur le nouvel identifiant que s'il n'a jamais été personnalisé (`display_username = username`) — préserve un nom d'affichage choisi par un admin.
Déconnexion (v2.8.7) : un seul chemin, `POST /api/auth/logout` (`AuthController`, effacement contrôlé du cookie `SESSION`), appelé partout côté frontend (`useDeconnexion.js`, `SidebarNav.vue`, `DrawerNav.vue`) — le filtre de logout par défaut de Spring Security sur `/logout` n'est plus utilisé, pour n'avoir qu'un seul chemin documenté et testé.
